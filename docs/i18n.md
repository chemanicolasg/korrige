# Traducción de la aplicación del profesor

La aplicación se escribe en castellano y se traduce al catalán (`ca`) y al inglés (`en`)
con un sistema tipo gettext: **el texto en castellano es la clave**.

```tsx
import { tr, trn } from '../i18n/app';            // ajusta la ruta relativa

<button>{tr('Guardar cambios')}</button>
<p>{tr('{n} de {total} exámenes', { n: shown.length, total: all.length })}</p>
<p>{trn('Imprime al <b>100 %</b>, nunca con «ajustar a página». {link}', { link: <Link to="/app/guia">{tr('Ver la guía')}</Link> })}</p>
placeholder={tr('Buscar por nombre…')}  aria-label={tr('Buscar examen')}
```

- `tr(texto, huecos?)` devuelve un `string`. Los huecos van entre llaves.
- `trn(texto, huecos?)` devuelve nodos de React: admite `<b>…</b>` dentro del texto (ninguna otra etiqueta)
  y huecos que sean elementos (enlaces, botones, `<span>`…).
- Son funciones normales, no hooks: valen en componentes, en constantes de módulo y en `src/lib`.
  Cambiar de idioma recarga la página.
- Fechas y números: `fmtDate`, `fmtDateTime`, `fmtNum` (de `components/ui`) ya usan el idioma activo.
  Si un archivo llama a `toLocaleString('es-ES', …)`, cámbialo por `bcp()` de `i18n/app`.

## Reglas

1. **El castellano no cambia ni una coma.** Con el idioma por defecto la pantalla debe quedar
   idéntica carácter a carácter (los tests de navegador buscan esos textos). No reescribas frases:
   si una frase mezcla texto y variables, conviértela en una clave con huecos que reproduzca
   exactamente el mismo resultado.
2. El primer argumento de `tr`/`trn` es **siempre un literal** (comillas simples, dobles o
   backticks sin `${}`), nunca una variable ni una concatenación: un test lo extrae del código.
   Para elegir entre dos textos: `cond ? tr('A') : tr('B')`, no `tr(cond ? 'A' : 'B')`.
3. Plurales: una clave por forma (`n === 1 ? tr('1 examen') : tr('{n} exámenes', { n })`),
   respetando lo que ya mostraba el castellano.
4. Añade cada clave a los dos diccionarios (`ca` y `en`) del módulo que te toque en
   `src/i18n/app/<módulo>.ts`. La traducción debe conservar los mismos huecos `{así}` y el mismo
   número de `<b>`.
5. **No traduzcas** (déjalo como está): `data-testid`, clases CSS, rutas, nombres de tablas y
   columnas, códigos de error, claves de `localStorage`, nombres de acción de auditoría, valores
   que se guardan en la base de datos, datos de ejemplo de la demo, marcas («Korrige», «Korrige Plus»,
   «Korrige Academy», «Moodle», «Excel»), ni comentarios.
6. Textos que **se guardan** en la base de datos (incidencias de una hoja, motivo de exclusión,
   notas de la plantilla…): se siguen guardando en castellano y se traducen **al mostrarlos**
   si son un texto fijo (`tr(valorGuardado)` no vale: el test exige literal; usa un mapa
   `{ 'Texto guardado': tr('Texto guardado') }` o un `switch`). Los que llevan datos variables
   dentro se dejan como están.
7. Mensajes de error que vienen del servidor (Postgres) llegan en castellano: no se tocan.
8. No cambies lógica, estructura de componentes, ni archivos que no te correspondan. No añadas
   dependencias. No ejecutes los tests de navegador (`npm run test:e2e`) ni arranques servidores.
9. Al terminar, deben pasar: `npx tsc --noEmit -p .` y `npx vitest run tests/i18n.test.ts`
   (este último puede fallar por claves de **otros** módulos que aún se estén traduciendo:
   solo importan las de tus archivos).
